# Portable replay bundles

A bundle captures the inputs for a completed file-backed run. Move the directory
to another location and replay without the original model, experiment, data,
receipt or result files:

```sh
./build-arrow/fathom run models/data/workforce.ir.json --out workforce.csv
./build-arrow/fathom bundle workforce.csv.manifest.json --out workforce-bundle
# Move or copy workforce-bundle as a whole directory.
./build-arrow/fathom replay workforce-bundle --threads 8
./build-arrow/fathom replay workforce-bundle --out replayed.parquet
./build-arrow/fathom verify-results replayed.parquet --embedded
```

`bundle` requires exactly a file-backed manifest and `--out DIRECTORY`. The
destination must be new, with an existing parent directory. It captures the
recorded source files only if their bytes still match the run. It does not need
the original result file, run a simulation, or assert that the current build can
reproduce the numeric result. A successful command prints a JSON verdict with
`scope: input-bundle`, the original manifest ID and the destination.

`replay` accepts either a manifest file or a bundle directory. Its options remain
`--threads`, `--out` and `--format`. Without output it reports numeric verification;
with output it publishes only after the original ordered numeric digest matches.
Replay of a version-0.2 receipt preserves the original manifest ID, row lineage
and embedded receipt, including the original input and output paths. Those paths
describe the original run, not the physical locations used for bundled replay.
No replacement receipt or new sidecar is created. CSV verification requires
retaining the original manifest object from the bundle descriptor as a sidecar.

## Directory contract (bundle version 0.1)

```text
bundle.json          # {"bundle_version":"0.1", "manifest":{...}}
model.json           # original model file bytes
experiment.json      # original experiment bytes, only if present
data/
  0.csv              # first manifest data binding
  1.parquet          # second binding, if present
```

Data member names use the binding's position in the original manifest's data
array and its source suffix (`.csv`, `.parquet`, `.arrow` or `.ipc`). The model's
declaration order may differ. Absolute source paths, relative paths, names in
different directories, and multiple bindings to the same source are captured
independently. The bundle holds raw model, experiment and data contents; it is
not a runtime environment, archive format or compressed container.

The [descriptor schema](../ir/schema/ankurafathom-bundle.schema.json) references
the existing manifest schema. The original manifest's checksum protects its
content, and its raw/canonical hashes bind each captured input. No new content
identity replaces the original run ID. As with manifests, this is an integrity
contract, not authentication: someone replacing a receipt and all its inputs
consistently can produce another internally valid bundle.

## Validation and resolution

Before simulation, replay requires exactly the expected member inventory.
Symlink roots/members, special files, unexpected directories/files and missing
members reject. Directory ancestors of the selected root may resolve through
ordinary filesystem aliases; the selected root itself must be a real directory.
Member paths are generated by the implementation, never taken from a configurable
archive/member path map. Original recorded absolute paths are metadata and are
not opened during bundled replay.

The raw model and experiment must match both file and canonical JSON identities.
Each data declaration must match the captured model, its recorded resolution,
and its actual bundled bytes. The normal loader then applies the same schema,
units, mapping and data validations to those copies. Canonical table hashes,
effective parameters, expanded scenarios, replications and seed must agree with
the original receipt. The loaded immutable snapshots supply these checks; simply
copying hashes from the receipt cannot establish a match.

Only physical input resolution changes. Replay keeps the existing strict build,
platform, precision and numeric comparison policy. A bundle made from a different
build may be captured successfully and then reject on replay with
`IR_REPLAY_MISMATCH`. Relocatable input files do not establish cross-platform
numeric reproducibility, include dependent libraries, or relax source identity.
In particular, a whitespace-only edit still violates a captured raw file hash.

Supported receipts are file-backed versions 0.1 and 0.2. Version-0.1 replay retains
its legacy output schema. API version-0.3 memory receipts remain unsupported:
their original raw JSON byte spans are not retained as files. Embedded-manifest
replay, remote URI inputs, optional data fallbacks and general binding composition
remain separate work. CSV-only builds can replay bundles for their supported
models; table-bound models still require the Arrow-enabled data loader.

## Publication, limits and errors

Capture stages files in a private sibling directory, checks the completed copy,
and renames that directory into place. Failure cleans up the private staging
directory and does not replace an existing destination. Input files are copied,
not moved. Replay rejects output anywhere inside its input bundle, including new
paths, and rejects existing hardlink/symlink aliases to its members.

Each member is limited to 256 MiB and the captured/read file bytes to 1 GiB in
total, with at most 1,024 data bindings. These are encoded-file limits, not decoded
memory budgets. Results and decoded tables remain materialized. There is no
directory-fsync durability guarantee or defense against another process changing
paths concurrently with validation/publication. Do not mutate a bundle during
capture or replay.

Malformed inventories, changed bytes, unsupported layouts and limits report
`IR_BUNDLE`; invalid manifests retain `IR_MANIFEST`; build/input-policy or numeric
disagreement retains `IR_REPLAY_MISMATCH`. Existing model/data loader diagnostics
still apply. Unsupported memory receipts report `IR_REPLAY_UNSUPPORTED`; command
and overwrite-policy errors can report `IR_USAGE`, and staging creation failure
reports `IR_IO`. Failed replay does not replace an existing output.

The CLI contract removes the original source directory and relocates each bundle
before replay at 1/8/32 workers. It checks deterministic and stochastic model modes,
all three data-binding kinds and CSV/Parquet/IPC input encodings, generated designs,
multiple bindings, independent numeric hashes, corruption rejection, member aliases,
size limits and publication cleanup. See the current session log for measured
normal, sanitizer, CSV-only and installed-package coverage.
