Checkpoint 23 — versioned shared C interface:

- Added `runtime/include/ankurafathom/c_api.h` and the `fathom_c_api` shared target,
  producing `libankurafathom` with ABI/SONAME major 1. CMake now enables C11 as well
  as C++20; the underlying static libraries are position-independent. macOS export
  lists and Linux version scripts restrict the interface to ten declared C symbols.
  Local symbol inspection confirms only those ten are exported from the dylib.
- Opaque model/results handles support JSON byte spans or file loading, single
  runs, explicit/grid/LHS/Sobol experiments, 1–256 workers, seed overrides through
  uint64 max, ordered observation access and the existing ordered numeric SHA-256.
  Results own their trajectories independently of model and caller-buffer lifetime.
  Output IDs/digests remain borrowed until result release. NULL frees are safe;
  invalid/stale/wrongly typed handles remain outside the caller contract.
- Memory and file inputs share JSON parsing and model validation. Experiments
  share one validator/expander with the CLI. Raw NUL bytes and trailing JSON reject;
  input spans are bounded to 256 MiB. Bound-data JSON requires an absolute base
  directory. Memory identity records captured raw/canonical hashes with an empty
  source path; no replayable-file provenance is fabricated.
- Status-returning calls contain C++ exceptions. Fixed-storage thread-local
  diagnostics preserve IR codes/pointers and flag overlong or embedded-NUL pointer
  truncation. Successful calls clear that thread's error; queries and frees preserve
  it. Creation destinations must point to NULL and remain NULL on failure; scalar
  and observation outputs stay unchanged on failure. Failed experiment workers
  publish no partial result handle. Allocation-failure translation is implemented;
  allocation fault injection is not claimed.
- A pure C11 executable links the shared library and checks an independent Euler
  recurrence, ownership, discarded input buffers, result lifetime after model free,
  null/argument/version/seed/thread controls, uint64 index limits, unchanged outputs,
  late worker failure, long and embedded-NUL diagnostics, and simultaneous model
  runs with isolated thread-local errors.
- A second C-compiled consumer emits exact IEEE bits and borrowed output IDs. The
  Python verifier passes 79 comparisons / 10,989 observations in normal/sanitizer
  Arrow builds, and 55 / 9,923 without Arrow. Coverage includes SD, DES, ABM, agent
  pools, hybrid, all three bound-data kinds, file and memory loading, 1/8/32 workers,
  all scenario designs, maximal seed override and signed zero. Numeric hashes match
  independent hashlib. CLI parity demonstrates interface equivalence, not a new
  independent simulator or fresh scientific-accuracy acceptance.
- Final affected regressions pass 40/40 normal (40.08 seconds), 40/40 ASan/UBSan
  (116.15 seconds), and 40/40 CSV-only (11.06 seconds). The prebuilt Arrow SDK itself
  is not sanitizer-instrumented. IR schema conformance also passes 52 valid fixtures,
  thirteen interaction/six generator cases, 412 structural invalid and 248 semantic
  invalid cases after the loader refactor. Configured suite: 266 Arrow-enabled /
  264 CSV-only. No new full-suite run or remote CI execution is claimed.
- Added `docs/C_API.md`; updated source fingerprints to include the public C header,
  CI targets/tests, plan, semantics and status. M6 remains in progress. Next is Arrow
  C Stream export with explicit release/lifetime checks, then the nanobind package.

Checkpoint 24 — independently owned Arrow C Streams:

  and Arrow's standard `ExportRecordBatchReader`, with the owning shared-pointer
  `TableBatchReader` constructor. Each export owns its buffers independently of
  model/result handles. A temporary release guard makes publication transactional.
  The stream is a batch interface over materialized results, not live simulation
  streaming or bounded total memory. Batches are currently capped at 65,536 rows.

  and previously released destinations are accepted. CSV-only builds report
  unavailable without modifying the destination. Stream callbacks use Arrow's
  errno/per-stream diagnostic contract, separate from Fathom's thread-local status.
  Consumers serialize callbacks per stream and keep the library loaded until all
  streams, schemas and arrays have been released.

  preserving its license/notice. The public C header requires no C++ SDK include.
  Native C++ consumers also compile with the SDK header first; the implementation

## Checkpoint 30 — Portable file-backed replay bundles

- Added `fathom bundle run.json --out DIRECTORY` and directory input to `fathom

  order and supported file suffixes; no archive path map is interpreted. The
  original manifest and numeric IDs survive relocation and replay output.
- Creation verifies raw files against the completed run, stages a private sibling
  directory, validates the captured model/data/scenario identities, then renames
  it into place. Existing destinations reject and failures clean staging. Packing
  captures inputs without asserting that the current build or recorded numeric
  digest can replay; replay separately enforces the original strict build policy
